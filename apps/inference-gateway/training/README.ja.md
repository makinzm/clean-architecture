# モデルのトレーニング (Inference Gateway)

このディレクトリでは、機械学習のセマンティックランキングモデルのデータ前処理、ファインチューニング、評価、およびONNX変換パイプラインを管理します。

## 対象モデルの概要

ここで学習しているモデルは **Cross-Encoder（クロスエンコーダー / リランカーモデル）** です。
現在のベースモデルには `BAAI/bge-reranker-base` などの最先端(SOTA)のランキングモデルを採用しています。

### 入力と出力の関係性

このモデルの役割は、「ある検索クエリに対して、対象のドキュメントがどれくらい関連しているか（正解か）」を高精度にスコアリングすることです。

- **入力 (Input):**
  - モデルは **(クエリ, ドキュメント)** のペアを同時に入力として受け取ります。
  - 本プロジェクトの文脈においては以下のようにマッピングされています。
    - **クエリ (Query):** GitHub Issue の `Title` (タイトル) 
    - **ドキュメント (Document):** GitHub Issue の `Body` (本文・解決策など)
  - Bi-Encoder（ベクトル検索でよく使われる手法）とは異なり、Cross-Encoderはクエリとドキュメントのテキストを結合し、TransformerのSelf-Attention層で単語レベルでの深い関係性を計算します。

- **出力 (Output):**
  - **関連度スコア (Relevance Score):** `0.0` から `1.0` までの連続値（回帰タスクとしてのスコア）。
  - `1.0` に近いほど、そのドキュメント（本文）がクエリ（タイトル）に対して非常に適切な内容・回答であることを意味します。
  - `0.0` に近い場合は、全く関係のないドキュメントであることを示します。

### 実運用での使われ方（推論時）
1. ユーザーが検索クエリを入力します。
2. （このシステムの外で）まず軽量なベクトル検索等を用いて、関連しそうな上位数十件のドキュメントを高速に取得します。
3. **ここで学習したCross-Encoderモデル** が登場し、クエリと取得した各ドキュメントのペアに対して精緻なスコアリングを行います。
4. スコアの高い順に並び替え（リランキング）を行い、最終的な最適な結果をユーザーに返します。

## トレーニングのワークフローと要件

再現性の担保と、コードとモデルウェイトの追跡を完全にするために、**すべてのトレーニングレポートとONNX出力は現在のGitのコミットハッシュに紐付けられます**。

全体の流れは以下のようになります：

1. **コードの変更**: `train.py` や `conf/config.yaml` などを修正します。（事前に `eda/` フォルダにあるEDAスクリプトを回してデータ分布を確認することを強く推奨します）。
2. **コミット**: 学習を実行する前に変更をコミットします。
   ```bash
   git add .
   git commit -m "chore(ml): BGEモデルの設定を変更"
   ```
3. **学習の実行**:
   ```bash
   uv run train.py
   ```

### 出力ファイルの構成
スクリプトはGitのコミットハッシュ（例: `ebd5060`）を用いて、以下の出力を自動生成します：
1. **一時的なPyTorchモデル**: `outputs/tmp_pytorch_model_<hash>` に保存されます（ルートディレクトリを汚さないため）。
2. **ONNXエクスポート**: PyTorchモデルは推論向けにOptimumで変換され、`apps/inference-gateway/server/weights/pointwise_<hash>.onnx` として出力されます。
3. **学習評価レポート**: 日付の階層ディレクトリに、評価指標（MSE, R2など）を記載したマークダウンファイルが出力されます：`reports/YYYY/MM/DD/<hash>.md`。
